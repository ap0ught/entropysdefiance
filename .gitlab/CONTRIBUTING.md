# Contributing to Entropy's Defiance

First off, thank you for considering contributing to Entropy's Defiance! This project was created through AI-assisted development, and contributions that maintain this approach are welcome.

## Understanding Vibe-Coding

Before contributing, it's important to understand the project's vibe-coding approach:

- **AI-Assisted Development**: The codebase was primarily generated through interactions with AI
- **Human-AI Collaboration**: Features emerged from dialogue between human creativity and AI capabilities
- **Prompt-Based Creation**: Code structures and solutions were guided by natural language prompts
- **Iterative Refinement**: The app evolved through multiple cycles of AI generation and human feedback

Contributions should respect this unique development methodology.

### Reporting Issues

When submitting an issue, consider:

- How the AI-generated solution might be improved
- Specific prompts that could help an AI better understand the problem
- Areas where the AI-generated code might need human refinement
- How the user experience could be enhanced through better AI-human collaboration

### Suggesting Enhancements

Enhancement suggestions should consider the AI-assisted nature of the project:

- Frame ideas as high-level concepts that could be implemented with AI assistance
- Consider both functional improvements and how they might be achieved through AI guidance
- Suggest prompt patterns that could help generate the desired features
- Think about how AI strengths could be leveraged for your suggestion

### Code Contributions

#### Making Contributions

The preferred way to contribute is through vibe-coding:

1. Use AI assistance to generate code changes based on your ideas
2. Document the prompts/conversations that led to your solution
3. Refine the AI-generated code as needed
4. Include notes about the AI-human collaboration process in your merge request

Traditional code contributions are also welcome, but should aim to maintain consistency with the AI-generated portions of the codebase.

#### Submitting a Merge Request

1. Push your branch to your fork: `git push origin feature/amazing-feature`
2. Create a merge request from your branch to the main repository
3. Fill out the merge request template with details about your changes, including how AI was used
4. Respond to any feedback during the review process

## Styleguides

### Git Commit Messages

- Consider mentioning AI assistance in commit messages when relevant
- Use the present tense ("Add feature" not "Added feature")
- Use the imperative mood ("Move cursor to..." not "Moves cursor to...")
- Limit the first line to 72 characters or less

### Kotlin Styleguide

- Follow the [Kotlin Coding Conventions](https://kotlinlang.org/docs/coding-conventions.html)
- Use descriptive variable names
- Add comments for complex logic
- Structure your code into small, focused functions

### UI Conventions

- Follow [Material Design guidelines](https://m3.material.io/)
- Maintain consistent UI patterns throughout the app
- Ensure all UI elements are accessible
- Support both light and dark themes

## Additional Notes

### Issue and Merge Request Labels

This section lists the labels we use to help us track and manage issues and merge requests.

- `bug`: Something isn't working
- `documentation`: Improvements or additions to documentation
- `enhancement`: New feature or request
- `good first issue`: Good for newcomers
- `help wanted`: Extra attention is needed

Thank you for respecting and contributing to the AI-assisted nature of Entropy's Defiance!
